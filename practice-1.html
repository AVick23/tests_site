После этой практики вы сможете:

📘 Часть 1. Исходные функции для тестирования

Создайте файл functions.py и добавьте туда 5 простых функций:

def add(a, b):
    return a + b


def multiply(a, b):
    return a * b


def is_even(n):
    return n % 2 == 0


def reverse_string(s):
    return s[::-1]


def max_of_two(a, b):
    if a > b:
        return a
    return b

Объяснение для вас: каждая функция делает что-то очень простое.

Эти функции идеально подходят для первых тестов. Я специально выбрал их, чтобы вы сосредоточились на механике тестирования, а не на сложной логике.

add(a, b)

Складывает два числа.

add(2, 3) → 5

multiply(a, b)

Умножает два числа.

multiply(2, 3) → 6

is_even(n)

Проверяет чётность числа.

is_even(4) → True

reverse_string(s)

Переворачивает строку.

reverse_string("hi") → "ih"

max_of_two(a, b)

Возвращает большее из двух чисел.

max_of_two(3, 7) → 7

✍️ Часть 2. Как писать тесты вручную (без assert)

Вот наш первый тест. Разберём его построчно, как будто вы впервые видите тесты.

from functions import add

def test_add():
    result = add(2, 3)

    if result != 5:
        print("❌ Ошибка: add(2, 3) должно быть 5")
    else:
        print("✅ Тест пройден")

test_add()
1

Импортируем функцию

from functions import add

Говорим Python: «возьми функцию add из файла functions.py». Теперь можно вызывать add() внутри теста.

2

Создаём тестовую функцию

def test_add():

Имя test_add выбрано специально: test_ — значит «это тест», add — значит «тестируем функцию add».

3

Вызываем функцию, которую тестируем

result = add(2, 3)

Сохраняем результат в переменную result. Если функция работает правильно — там будет 5.

4

Проверяем результат вручную

if result != 5:

Сравниваем то, что вернула функция (факт), с тем, что мы ожидаем. Это ключевой момент: тест — это сравнение ожидаемого с фактическим.

5

Сообщаем результат

print("❌ Ошибка: ...")   # если неправильно
print("✅ Тест пройден")   # если правильно

В реальных тестах так никто не делает — но новичку важно увидеть механику.

6

Запускаем тест

test_add()

Без этого тест не запустится. Вручную тесты нужно запускать вручную. В pytest это будет делаться автоматически.

Итог: тест берёт функцию, вызывает её, сравнивает результат с ожидаемым, сообщает результат и запускается.

✅ Часть 3. Как писать тесты с assert

Тот же тест, но уже через assert — правильный, современный способ.

from functions import add

def test_add():
    assert add(2, 3) == 5
    assert add(0, 0) == 0
    assert add(-1, 1) == 0

test_add()
print("Все тесты пройдены!")

🧠 Что такое assert?

assert — это встроенное ключевое слово Python, которое означает: «Проверь, что это выражение истинно. Если оно ложное — останови программу и сообщи об ошибке.»

Когда Python видит:

assert add(2, 3) == 5

он делает:

  1. вызывает функцию add(2, 3),
  2. получает результат, например 5,
  3. сравнивает его с ожидаемым 5,
  4. если совпало — идёт дальше,
  5. если не совпало — делает raise AssertionError, и программа падает.

🎯 Почему assert лучше ручных проверок?

Ручной тест: if, print, много строк, легко ошибиться.

Assert: одна строка вместо четырёх, автоматическая проверка, автоматическая ошибка, читается как английский.

Pytest — это просто надстройка над assert. Проверка остаётся такой же: assert something == expected.

⚖️ Часть 4. Ручной тест vs assert

Что сравниваем Ручные тесты assert
Проверка результата вручную через if автоматически
Ошибка вручную через print автоматически через AssertionError
Количество кода много одна строка
Читаемость низкая высокая
Похожесть на настоящие тесты нет да
Основа pytest нет да
Главное понимание: ручные тесты нужны только для того, чтобы понять механику. assert — это правильный, современный и удобный способ. Pytest — это просто надстройка над assert.

📝 Часть 5. Задания для самостоятельной работы

📝 Задание 1. Написать ручные тесты (без assert)

Создайте файл test_manual_more.py и напишите тесты вручную, как мы делали в Части 2:

result = multiply(2, 3)
if result != 6:
    print("Ошибка")
else:
    print("Ок")

Проверьте:

  • multiply: обычное умножение, умножение на ноль, отрицательные числа.
  • is_even: чётное → True, нечётное → False, ноль → True.
  • reverse_string: "hello" → "olleh", пустая строка → пустая, один символ → он же.
  • max_of_two: первое больше, второе больше, числа равны.

📝 Задание 2. Написать тесты с assert

Создайте файл test_assert_more.py и напишите те же тесты через assert:

def test_multiply():
    assert multiply(2, 3) == 6
    assert multiply(0, 5) == 0
    assert multiply(-2, 3) == -6

Что важно понять:

  • assert делает проверку автоматически,
  • если тест неверный → программа падает,
  • если верный → идёт дальше,
  • тесты становятся короче и понятнее.

📝 Задание 3. Специально сломать один тест

Это очень важная часть обучения:

  1. выберите любую функцию,
  2. напишите тест, который точно должен упасть,
  3. запустите тест,
  4. посмотрите, как выглядит AssertionError,
  5. поймите, как Python показывает место ошибки.

💥 Часть 6. Что происходит, когда тест падает

Пример сломанного теста:

def test_broken():
    assert add(2, 2) == 5  # специально неверно

test_broken()

Вы увидите:

Traceback (most recent call last):
  File "test_broken.py", line 4, in <module>
    test_broken()
  File "test_broken.py", line 2, in test_broken
    assert add(2, 2) == 5
AssertionError

Читаем сверху вниз:

Traceback — след ошибки. Файл и строка — где. Строка с assert — что упало. AssertionError — что не так.

Зачем специально ломать тест? Чтобы увидеть ошибку, понять, как Python её показывает, и перестать бояться падений тестов. Тест, который упал — это не катастрофа. Это сигнал, что тест работает.

❓ Часть 7. Вопрос — ответ

Что такое тестирование?
Сравнение ожидаемого результата с фактическим. Если совпало — тест пройден. Если нет — тест упал.
Почему сначала ручные тесты, а потом assert?
Чтобы понять механику: assert — это сокращение для ручной проверки. Если сразу дать assert, новичок не поймёт, что внутри него происходит.
Чем assert отличается от if?
if add(2, 3) != 5 — это условие. assert add(2, 3) == 5 — это утверждение. Первое требует дополнительного кода для ошибки, второе само останавливает программу.
Что произойдёт, если первый assert упадёт?
Программа остановится, остальные assert не выполнятся. AssertionError покажет, где именно.
Что делать, если тест упал?
Понять, что не так: код или тест. Исправить. Запустить снова. Если код правильный, а тест упал — значит, тест неправильный.
Почему assert — это шаг к pytest?
Потому что pytest использует assert внутри. Pytest просто делает выводы красивее, автоматически находит тесты и умеет параметризацию — но сердце всё то же: assert something == expected.
Почему «программа запускается» — это ещё не качество?
Потому что она может запускаться, но считать неправильно. Тестирование проверяет не «запустилось ли», а «правильно ли».

После выполнения этой практики вы:

  • понимаете механику тестирования,
  • умеете писать тесты вручную,
  • умеете писать тесты с assert,
  • умеете тестировать разные типы данных,
  • умеете читать AssertionError,
  • понимаете, зачем нужны тесты.
Главная мысль: тестирование — это систематическая проверка того, что функция возвращает ожидаемый результат на разных входных данных. Это не «запустить и посмотреть», а система: разные входы, ожидаемые выходы, сравнение.
