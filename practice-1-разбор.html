Титульный

📊 Что на слайде

Практическая работа №1
Тестирование простых функций в Python
Ручные проверки → assert

🎤 Речь преподавателя

Сегодня мы начинаем тему, которая отличает «код, который работает» от «кода, которому можно доверять». Это тестирование. Мы начнём с самого простого — ручных проверок, а потом перейдём к assert.

❓ Вопрос ученикам

Как вы думаете, что значит «протестировать функцию»?

✅ Ответ

Проверить, что она возвращает то, что должна, на разных входных данных.

➡️ Переход

Мы уже прошли теорию: верификация, валидация, QA, QC, дефекты. Но теория без практики — это просто слова. Сегодня — первый шаг в реальное тестирование.

Чем тестирование отличается от «просто запустить программу»?

✅ Ответ

Запуск показывает, что программа не падает. Тестирование проверяет, что она даёт правильный результат.

4

Главная мысль практики

📊 Что на слайде

Тестирование — это сравнение ожидаемого результата с фактическим.

🎤 Речь преподавателя

Запомните эту фразу. Всё тестирование сводится к одному: у нас есть ожидание, у нас есть факт, мы их сравниваем. Если совпало — тест пройден. Если нет — тест упал.

❓ Вопрос ученикам

Что такое «ожидаемый результат» и «фактический результат»?

✅ Ответ

Ожидаемый — то, что функция должна вернуть. Фактический — то, что она вернула на самом деле.

➡️ Переход

Теперь — к функциям.

5

Функции для тестирования

📊 Что на слайде 
def add(a, b):
    return a + b

def multiply(a, b):
    return a * b

def is_even(n):
    return n % 2 == 0

def reverse_string(s):
    return s[::-1]

def max_of_two(a, b):
    if a > b:
        return a
    return b
🎤 Речь преподавателя

Пять функций. Простые, но разные. add и multiply работают с числами. is_even возвращает логическое значение. reverse_string — строку. max_of_two — условная логика.

❓ Вопрос ученикам

Почему мы тестируем именно такие функции?

✅ Ответ

Они простые, но покрывают разные типы данных и разные типы результатов.

➡️ Переход

Начнём с add.

Она возвращает True или False, а не число.

7

Ручной тест: идея

📊 Что на слайде
  1. Вызвать функцию
  2. Сохранить результат
  3. Сравнить с ожидаемым
  4. Напечатать сообщение
🎤 Речь преподавателя

Это четыре шага любого теста. Сейчас мы делаем их вручную, чтобы вы увидели механику. Потом assert сделает то же самое, но короче.

❓ Вопрос ученикам

Почему мы сохраняем результат в переменную, а не сравниваем сразу?

✅ Ответ

Чтобы можно было посмотреть, что именно вернула функция, если тест упадёт.

➡️ Переход

Вот как это выглядит в коде.

8

Ручной тест: код

📊 Что на слайде 
from functions import add

def test_add():
    result = add(2, 3)

    if result != 5:
        print("❌ Ошибка: add(2, 3) должно быть 5")
    else:
        print("✅ Тест пройден")

test_add()
🎤 Речь преподавателя

Разберём по строкам. Импорт — берём функцию из другого файла. Функция test_add — это тест. Внутри — вызов, сравнение, вывод.

❓ Вопрос ученикам

Что произойдёт, если add(2, 3) вернёт не 5, а 6?

✅ Ответ

Напечатается «❌ Ошибка: add(2, 3) должно быть 5».

➡️ Переход

Разберём каждую строку отдельно.

9

Ручной тест: пошаговый разбор

📊 Что на слайде 
from functions import add          # 1. Импорт
def test_add():                    # 2. Создание теста
    result = add(2, 3)             # 3. Вызов
    if result != 5:                # 4. Сравнение
        print("❌ Ошибка")         # 5. Ошибка
    else:
        print("✅ Тест пройден")   # 6. Успех
test_add()                         # 7. Запуск
🎤 Речь преподавателя

Семь шагов. Каждый важен. Импорт — откуда берём функцию. Создание теста — что тестируем. Вызов — получаем факт. Сравнение — с ожиданием. Вывод — сообщаем результат. Запуск — без него тест не выполнится.

❓ Вопрос ученикам

Почему без test_add() внизу тест не запустится?

✅ Ответ

Потому что Python выполняет код сверху вниз, но функцию нужно вызвать.

➡️ Переход

Теперь — то же самое, но через assert.

10

Что такое assert

📊 Что на слайде

assert — это утверждение: «я утверждаю, что это истинно».
Если ложно — программа останавливается с AssertionError.

🎤 Речь преподавателя

assert — это встроенное слово Python. Оно читается как утверждение. Мы не пишем «если не равно — ошибка». Мы пишем «утверждаю, что равно». Если это не так — Python сам сообщит.

❓ Вопрос ученикам

Чем assert add(2, 3) == 5 отличается от if add(2, 3) != 5?

✅ Ответ

Первое — утверждение, второе — условие. Первое короче и понятнее.

➡️ Переход

Вот как выглядит тест с assert.

11

Тест с assert

📊 Что на слайде 
from functions import add

def test_add():
    assert add(2, 3) == 5
    assert add(0, 0) == 0
    assert add(-1, 1) == 0

test_add()
print("Все тесты пройдены!")
🎤 Речь преподавателя

Три строки вместо двенадцати. И каждая строка читается как утверждение: «add(2, 3) равно 5», «add(0, 0) равно 0», «add(-1, 1) равно 0».

❓ Вопрос ученикам

Что произойдёт, если первый assert упадёт?

✅ Ответ

Программа остановится, остальные assert не выполнятся.

➡️ Переход

Сравним ручной тест и assert.

Задание 3. Сломать тест

📊 Что на слайде 
def test_broken():
    assert add(2, 2) == 5  # специально неверно

test_broken()
🎤 Речь преподавателя

Это специальное задание. Мы ломаем тест, чтобы увидеть AssertionError. Это важно: тест, который упал — это не катастрофа. Это сигнал, что тест работает.

❓ Вопрос ученикам

Зачем специально ломать тест?

✅ Ответ

Чтобы увидеть, как выглядит ошибка, и перестать её бояться.

➡️ Переход

Вот что покажет Python.

16

Как выглядит AssertionError

📊 Что на слайде 
Traceback (most recent call last):
  File "test_broken.py", line 4, in <module>
    test_broken()
  File "test_broken.py", line 2, in test_broken
    assert add(2, 2) == 5
AssertionError
🎤 Речь преподавателя

Читаем сверху вниз. Traceback — след ошибки. Файл и строка — где. Строка с assert — что именно упало. AssertionError — что не так.

❓ Вопрос ученикам

Что делать, если тест упал?

✅ Ответ

Понять, что не так: код или тест. Исправить. Запустить снова.

➡️ Переход

Теперь — как правильно мыслить при тестировании.

17

Как мыслить при тестировании

📊 Что на слайде
  1. Понять, что должна делать функция
  2. Определить ожидаемый результат
  3. Вызвать функцию
  4. Сравнить
  5. Повторить для разных случаев
  6. Если упало — разобраться
🎤 Речь преподавателя

Это алгоритм тестирования. Он одинаков для любой функции. Сначала понимаем, что должно быть. Потом проверяем, что есть. Потом сравниваем.

❓ Вопрос ученикам

Что делать, если тест упал, а код правильный?

✅ Ответ

Значит, тест неправильный. Нужно исправить тест.
